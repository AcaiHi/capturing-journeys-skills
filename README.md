# capturing-journeys：系統做完之後，沿著使用故事把每一步拍下來

系統終於做完了，這時才發現最磨人的是**截圖**。想拍「求解結果」那張，得先登入、建好班表、填完一堆申請才看得到；好不容易拍完，回頭補一張才發現前面登入的是林雅婷，後面重拍變成了王小明，日期也對不上；過兩週改了側邊欄，根本不記得哪些圖已經跟現況不一樣。

這個 skill 讓 Claude 在系統完成之後，照著你的使用故事從頭走到尾，把每一步畫面拍成尺寸一致、資料連貫、隨時可以重拍的截圖，並替每張圖記下它的來歷。

---

## 它能幫你做什麼

- **圖序跟著故事走**：要拍哪些圖由使用故事導出，先列成清單給你確認，你點頭才開拍。還沒有故事的話，Claude 會先陪你一起寫。
- **資料前後一致**：畫面上的人名、日期、數量都從同一個地方取，改一處，所有圖跟著改。
- **知道哪些圖過時**：改了程式或資料之後，它能告訴你哪幾張圖可能已經跟現況不同，以及原因。
- **會變的圖會被點名**：演算法結果、AI 回覆這類重拍就可能不同的圖，會事先標出來，重拍後一定請你親眼看過。
- **錄影與標註**：靜態圖看不出過程的畫面（例如 AI 逐步回覆）可以改成錄影；也能在圖上框出重點，框會跟著元素走，原圖保持不動。
- **照實拍到 bug**：拍攝時發現 app 本身有問題，Claude 會照實際的樣子拍，告訴你哪裡怪，再問你要不要修，不會擅自改你的程式。

不用記任何指令，用平常的話說就好，例如「系統做完了，幫我依使用故事走一遍拍照」「我改了頁首，哪些圖要重拍？」「把第 3 章重拍」「幫求解結果那張標出開始求解按鈕」。Claude 會把工作拆成一份 todo 清單，一項一項勾，你隨時看得到做到哪裡。

---

## 一個例子：排班系統

假設你做了一個護理排班系統，故事大概是這樣：

> 內科病房護理長林雅婷在 2026-03-02 登入，建立三月份班表，看到 3 筆休假申請，按下「開始求解」，得到排好的班表與違規格數。

Claude 會從這段故事導出四張圖：登入畫面、建立班表、休假申請、求解結果，每張附一句圖說，先給你確認。其中「求解結果」在清單階段就會被標成「重拍可能會變」，因為求解器每次排出來的班表不一定相同，不會等到重拍時才嚇一跳。

「林雅婷」「內科病房」「2026-03-02」「3 筆」這些事實集中放在一個地方。哪天要把護理長換個名字，只改那一處，Claude 也會列出所有用到這個名字的圖。

## 拍攝與重拍是怎麼進行的

長流程會切成幾個段落，每段從自己的起點出發，所以重拍第 5 章不必先把第 3 章走一遍。資料要用真實系統跑，還是用模擬資料，Claude 會依流程長短、系統好不好啟動先跟你討論，由你決定。

每張圖都拍整個視窗，尺寸一致；拍之前會先確認畫面上真的是這一步該有的內容，避免拍錯頁還以為成功。拍完後 Claude 會逐張打開來看、連跑幾次確認穩定，最後回報警告、會變的圖，以及拍不到而略過的圖。

改版之後要重拍時，它會先把現有的圖備份起來，重拍完再依新舊差異大小排序給你看，舊圖不會被悄悄蓋掉。「哪些圖過時」是預測不是保證，所以改到頁首、側邊欄這類全站元素時，Claude 會建議直接整套重拍。

## 安裝

需要 Python 3 與 Node.js，專案要能用 Playwright（缺的話 Claude 會提醒你裝）。

1. 把這個資料夾放在 `~/.claude/skills/capturing-journeys-build/`。
2. 在前端專案根目錄跟 Claude 說「把 capturing-journeys 裝進這個專案」，或自己執行：

   ```bash
   python ~/.claude/skills/capturing-journeys-build/scripts/build.py sync --workspace .
   ```

   重複執行也沒關係，既有檔案不會被覆蓋。裝完後，專案裡會多一個放使用故事、截圖與圖片清單的資料夾。
3. 確認一下設定裡的網址、語系與時區是不是你要的。
4. **開一個新的 session**，skill 才會載入。

## 常見問題

**Q：一定要先有使用故事嗎？**
要，故事是拍攝的起點。沒有的話 Claude 會先和你一起寫，缺主角、單位、日期這類資訊時會問你。

**Q：假資料會不會很假？**
不會出現 test、foo、123 這類字樣，而是寫實的名稱、日期與數字；真實人名等敏感資料會先去識別化或遮蔽。

**Q：在不同電腦拍的圖會一樣嗎？**
不一定，Windows 和 Linux 的字型渲染不同。一組圖最好在同一台機器上拍完。

**Q：可以只重拍一張嗎？**
可以，直接跟 Claude 說要重拍哪一張就好。
