## stability 欄位

每張圖在 manifest 標 `stability`，表示**重拍後畫面會不會變**：

- `stable`：同樣的輸入拍出同樣的畫面。
- `volatile`：即使輸入沒變，重拍也可能不同。再填 `volatileBy`（可多個）說明原因。

要在清單階段就判斷，不要等重拍時才發現。判斷依據：這個畫面的內容是否來自演算法結果、真實 LLM、時間、隨機排序、非同步載入。
標記看**重拍時的資料來源**：用 mock 回傳固定值，重拍就拍得一樣，標 `stable`；用真實求解器或真實 LLM，才標 `volatile`。若之後要把 mock 換成真實系統，記得回頭改標。

## volatile 的處理策略

| volatileBy | 例子 | 策略 |
|---|---|---|
| `solver` | 排班結果、每次違規的人與格數不同 | 圖旁邊的說明與數字從**當次結果**核對或產生；標註框用元素對位，不用座標 |
| `llm` | AI 助理每次的提問略有不同 | 用連續錄影（見 [recording.md](recording.md)）；重拍後人工看過；相關文字依實際內容改寫 |
| `time` | 時間、日期、倒數 | 固定時鐘；留意固定後計時器不前進（見 [environment.md](environment.md)） |
| `async` | 按下確認後偶爾又顯示回草稿、載入動畫 | 先等明確的完成條件，再核對狀態，不對就重新載入 |
| `scroll` | 背景捲動位置不固定、暫時提示被拍進去 | 固定捲動位置，拍前清掉 hover、focus 與 toast |

能讓它固定就先固定：固定亂數種子，或把求解器、LLM 的回應 mock 成固定資料（做法見 [environment.md](environment.md)），固定後改標 `stable`。固定不了或不該固定時才維持 volatile。

重拍 volatile 的圖之後：
- **一定請使用者人工過目**，不要自動接受。
- 提醒使用者：凡是引用這張圖裡數字或結果的文字，都要依新的畫面重新核對，不要沿用舊數字。
  引用其他圖結果的圖，在 manifest 用 `derivedFrom` 指向來源圖，來源過時時 `check` 會列出它。
- `shoot()` 對 volatile 的圖不做文字雜湊比對（內容本來就會變），不帶 `--update-snapshots` 時也不比對像素，只跑守門斷言。
- `compare` 對 volatile 的圖差異必然偏大，那是正常現象，不要當成回歸；它們一律人工看。
- volatile 的圖不會因為「輸入沒變」而被 `check` 當成過時，但每次都另外列出提醒；使用者要求重拍整章時，照樣重拍並過目。

## 拍前整理

`shoot()` 已處理：等 `document.fonts.ready`、`mouse.move(0, 0)`、`blur()` 目前焦點元素。
其餘由 spec 負責：

- 內容在內層捲動容器時，捲**那個容器**，並預留約 16px，標題才不會被裁切；不要只捲 window。
- 要等的東西用明確條件（某段文字出現、請求回來、動畫計數結束），不只靠 `networkidle`。
  打字動畫與版本重載可以用 `expect.poll` 計次數。
- app 載入後會重新導向或受限制於深層連結：先載入一個允許的頁面並等穩定，再用 `history.pushState` 加 `popstate` 在前端切換路由。
- 拍前確認 UI 已經定案。介面文字、圖示、命名還在改的時候，先定清單，延後拍。

## 驗收細節

- 逐張打開 PNG。
- 連跑 3 次：`npx playwright test -c docs/ui-inventory --retries=0`，任何失敗或 `flaky` 都代表缺等待。
- `stale.py dups`：像素完全相同的兩張圖，確認是不是重複拍了同一個畫面。
- 容許誤差已在 config 設得很小，因為太寬會讓「只改了幾個字」的畫面偵測不到；文字變更另外靠 `shoot()` 的文字雜湊把關。

## 失敗與漏抓

- 同一檔案內若多個畫面串成一條鏈，第一個失敗，後面全部被跳過。每章盡量讓 test 彼此獨立，從檢查點開始，而不是串成長鏈。
- 重拍前先刪舊 PNG，原因見 SKILL.md 的重拍段落。
- 改了畫面文字後，不要只靠不帶 `--update-snapshots` 的檢查：文字變更若在容許值之內會被放過。以 `stale.py check` 列出的清單為準，必要時暫時把容許誤差設為 0 掃一次。
